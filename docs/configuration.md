# Configuration

Six variables are required. Everything else is optional, and most of it lives in Settings > Server; a variable that backs a Settings > Server field wins over the stored value and locks the field.

`apps/server/test/config-docs.test.ts` checks this page against the code, the instance settings, the injector, the Agent Skill, the compose files and `.env.example`: every variable read needs a row here and a place in [Where each setting lives](#where-each-setting-lives), and no row may name an unread variable.

## The basic deployment

| What | Variables |
|---|---|
| Where people reach the server | `PUBLIC_URL` |
| The secret that signs sessions and encrypts stored secrets | `BETTER_AUTH_SECRET` (or `AUTH_SECRET`) |
| Your sign-in provider | `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET` |
| Who administers the server | `ADMIN_EMAILS` |

```sh
cp .env.example .env                                 # or: scripts/gen-secrets.sh https://feedback.example.com
$EDITOR .env                                         # the required block at the top
docker compose up -d --build
curl -s https://feedback.example.com/api/health      # {"ok":true,...}
```

Until an admin adds email domains in Settings > Server, Sign-in, only `ADMIN_EMAILS` can sign in ([Who gets in](#who-gets-in)). `PUBLIC_URL` is the https address of your TLS proxy; the server refuses to start on a non-localhost `PUBLIC_URL` with the dev auth secret. Postgres and Garage bind `127.0.0.1`; `scripts/gen-secrets.sh` replaces their dev credentials too.

### Compose files

| File | When you use it |
|---|---|
| `docker-compose.yml` | Always: the server, Postgres and Garage. Passes all of `.env` to the server (`env_file`). |
| `docker-compose.whisper.yml` | Local transcription with whisper.cpp. |
| `docker-compose.mail.yml` | The paused mail (`FEATURE_EMAIL`, D-171), with Mailpit. |
| `docker-compose.dev.yml` | Development and e2e only: the mock OIDC provider, password sign-in, rate limits off, paused feature flags. Never in a deployment. |
| `docker-compose.coolify.yml` | Coolify, in place of all of the above ([Coolify](#coolify)). |

## Where each setting lives

D-194. **Required**: boots the server. **Wiring**: filled in by compose or Coolify. **Settings > Server**: instance admin, at runtime; the variable locks the field. **Workspace**: workspace admin, no variable. **Optional environment**: read at start, another container's, or image-dependent. **Dev and tests**, **Paused** and **Build** stay out of deployed compose files.

| Setting | Where | Why there |
|---|---|---|
| `PUBLIC_URL` | Required | Cookies, the OAuth redirect URI and CSRF checks are built from it before anyone can sign in. |
| `BETTER_AUTH_SECRET`, `AUTH_SECRET` | Required | Signs sessions and derives the keys of sealed values, the stored API key included, so it cannot live in the database it protects. |
| `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET` | Required | Nobody, the admin included, can sign in without the provider, and the client secret should not sit in a table an admin page edits. |

## Settings > Server

Instance admins only (others get 404). Each section saves only changed fields; an emptied field returns to its default.

| Section | Fields |
|---|---|
| Sign-in | The provider and its redirect URI, read-only from the environment, with Test discovery URL; allowed email domains, the button name, scopes |
| Transcription | Provider (off, local whisper.cpp, an OpenAI-compatible endpoint), API key, model, endpoint, whisper.cpp URL, languages, timestamps, chunk length, parallel requests, with Test connection |
| Capture defaults | Site access (all sites, or project origins only), masking preset and trace step window for new projects, longest recording |
| Sharing and export | Share link lifetime, export page size, the extension's "report a problem" link |
| Limits | Longest audio transcribed, hosted transcription minutes per month, recording link uploads per address in 10 minutes |

- **Precedence**: variable (field shows "Set by environment"; the API answers `locked_by_env`), then stored value, then default.
- **No restart**: other replicas re-read within 15 seconds.
- **API key**: sealed with AES-256-GCM under a key derived from `BETTER_AUTH_SECRET`; only the last four characters come back. Changing the auth secret makes it unreadable.
- **Test buttons**: Test connection calls `<endpoint>/models` (or `<whisper.cpp URL>/`); Test discovery URL checks the scopes against `scopes_supported`. Both use unsaved form values.
- **API**: `GET` and `PATCH /api/v1/admin/settings`, `POST /api/v1/admin/settings/test`; session only, no personal tokens.
- **Storage**: table `instance_setting`, row `instance`.

### Workspace settings

Settings, General, New projects: the masking preset and trace step window for new projects (and for `POST /api/v1/workspaces/<id>/projects` without them). Empty follows the instance's Capture defaults.

### Site access

Settings > Server, Capture defaults, Site access, or `SITE_ACCESS` (D-200).

| Mode | The extension | The server |
|---|---|---|
| All sites (`all`, default) | Capture scripts run everywhere except this server and the reviewer's blocked sites. All-sites access is a required permission (D-202). | The first capture on an unknown origin makes a project named after the host, with the workspace's defaults. |
| Project origins only (`projects`) | Capture scripts run on project origins only; no network metadata elsewhere (D-126). | Other origins get 403 `origin_not_allowed`. No automatic projects. |

Projects list exact origins (`http://localhost:5173`) and domains (`*.nuru.sh`: the domain and every subdomain, https only unless `http://*.nuru.sh` is listed). Exact beats domain; longer domain beats shorter. Merging two projects moves the second's origins and captures into the first.

### Who gets in

- **Bootstrap (D-194)**: on a non-localhost `PUBLIC_URL` with no allowed domains and no admin yet, only verified `ADMIN_EMAILS` addresses get in. With `ADMIN_EMAILS` empty there, nobody does. On localhost without `ADMIN_EMAILS`, the first account is the admin.
- **Allowed domains**: checked at every sign-in (`email_verified` not false, domain listed, Google `hd` listed when present) and at every request; removing a domain cuts its sessions, API tokens, extension tokens and MCP agents. Empty after bootstrap admits anyone the provider signs in.
- No group-based allowlists.
- Captures and comments store the author's issuer, `sub`, email and name. Anonymous share-link comments and recording-link uploads carry no account.

### Google Workspace

OAuth client of type "Web application", redirect URI `https://<your host>/api/auth/callback/oidc`, consent screen "Internal". Then:

```sh
OIDC_ISSUER=https://accounts.google.com
OIDC_CLIENT_ID=1234567890-abc.apps.googleusercontent.com
OIDC_CLIENT_SECRET=GOCSPX-...
ADMIN_EMAILS=you@yourcompany.com
```

Add `yourcompany.com` to the allowed domains after the first sign-in.

## Transcription

Microphone audio of recordings, traces and voice notes becomes WebVTT on the server (D-087). Off until a provider is picked in Settings > Server, Transcription or set by `TRANSCRIBE_PROVIDER` (D-194):

- `local`: whisper.cpp (`docker-compose.whisper.yml`, or `COMPOSE_PROFILES=whisper` on Coolify). No key, no cost, audio stays on the server. Good English, unusable Swahili.
- `openai`: an OpenAI-compatible endpoint, `gpt-transcribe` by default. Paid, sends audio to the provider, far better on Swahili and faster on CPU-only hosts.
- `none`: off.

A key alone does not switch the provider.

| Variable | Default | Example | Purpose and when to change |
|---|---|---|---|
| `TRANSCRIBE_PROVIDER` | `none` | `openai`, `local` | Settings > Server, Transcription. `none`, `local` or `openai`. |
| `TRANSCRIBE_MODEL` | `gpt-transcribe` | `whisper-1` | Settings > Server, Transcription. Model id; Groq takes `whisper-large-v3-turbo`. |
| `TRANSCRIBE_API_KEY` | `OPENAI_API_KEY` | `sk-...` | Settings > Server, Transcription (stored sealed). Bearer token for `openai`. |
| `OPENAI_API_KEY` | empty | `sk-...` | Fallback for `TRANSCRIBE_API_KEY`; locks the same field. |
| `TRANSCRIBE_BASE_URL` | `https://api.openai.com/v1` | `https://api.groq.com/openai/v1` | Settings > Server, Transcription. Endpoint with `/v1`; posts to `<base>/audio/transcriptions`. |
| `TRANSCRIBE_LANGUAGE` | empty (detect) | `sw,en` | Settings > Server, Transcription. ISO 639-1 codes. Empty works best for mixed languages. |

### Limits of the hosted provider

- **Size**: 25 MB per request. Audio is cut at pauses into chunks of at most 30 s, 32 kbps Opus (about 120 KB each); length is bounded only by `TRANSCRIBE_MAX_MINUTES`. `native` sends files up to 24 MB whole.
- **Cost**: `gpt-transcribe` is $0.0045 a minute, billed per second, plus about 2% for chunking. Five minutes: about $0.02; an hour: about $0.28. `TRANSCRIBE_MONTHLY_MINUTES=6000` caps a month near $27; the cap is reserved before sending. Silence is not sent.
- **Failures**: four tries per request on 429, 5xx, timeouts and network errors, honouring `Retry-After`; 401 and quota errors fail at once. Five job retries, then the transcript is marked failed.
- **Timestamps**: `gpt-transcribe` returns no times; the server spreads sentences over speech within each chunk (median offset 0.8 to 1.1 s).

### Privacy

With `openai`, only microphone audio goes to `TRANSCRIBE_BASE_URL`: no video, screenshots, console, network data or names. OpenAI does not train on `/v1/audio/transcriptions` audio or keep it for abuse monitoring, and the endpoint is eligible for Zero Data Retention. Other providers have their own terms.

Each WebVTT file starts with `NOTE Machine transcript (<model>, language <codes>)`, and MCP tools mark transcripts as data.

### Swahili and English quality

Measured on FLEURS read speech (`docs/research/transcription.md`; lower is better, word error rate and, for Swahili, character error rate):

| Provider and model | English | Swahili and English, alternating | Swahili |
|---|---|---|---|
| `openai`, `gpt-transcribe`, 30 s chunks (default hosted) | 7.0% | 15.1% | 25.6% words, 13.9% characters |
| `openai`, `whisper-1` | 26.2% (drops sentences) | 66.9% | 53.7% words, 29.0% characters |
| `local`, whisper.cpp `base` (default) | 17.5% | 76.3% | 94.8% words, 54.9% characters |
| `local`, whisper.cpp `small` | 38.2% (drops sentences) | 69.2% | 80.1% words, 38.4% characters |

Swahili word error rates overstate the damage (numbers spelled out, compounds split). Use `openai` for Swahili or code-switched speech. Groq's Whisper costs about a seventh of `gpt-transcribe` with Whisper's weak Swahili.

## Agent hand-off

- **One capture**: `curl -fsSL -H "Authorization: Bearer $TOOLBAR_TOKEN" "<server>/api/v1/recordings/<id>/folder" | tar xz` writes `.feedback/<id>/` (README.md, feedback.json, spans.jsonl, annotations, keyframes, outline, OCR text, voice, console, network, raw). Needs a workspace member's token. A share URL with `Accept: text/markdown` or `.md` answers a summary whose first line is this command.
- **Bulk export (D-183)**: `<server>/api/v1/feedback/export` writes `.feedback/INDEX.md` (under about 8k tokens: per-capture table, routes with the most problems, grouped errors and failing requests, repeated reviewer words) and one folder per capture. Filters: `workspace`, `project`, `folder` (`none` for unfiled), `status` (`unresolved` default, `resolved`, `all`), `since`, `until`, `kind`, `creator` (id, email or `me`), `limit` (default 50, max 200). Pages end at `limit` or `EXPORT_MAX_MB`; the `x-next-cursor` header and the end of INDEX.md give `&cursor=...`, and later pages write `INDEX-2.md` and so on. `GET /api/v1/feedback` (JSON) and `GET /api/v1/feedback/index` (INDEX.md only) take the same filters.
- **MCP**: `get_feedback_folder`, `get_feedback_file`, `resolve_feedback`, `list_feedback`, `get_feedback_index`.
- **Skill**: `<server>/api/v1/skill` (`skills/open-toolbar-feedback/SKILL.md`).
- **Webhooks**: `feedback.created` (with `data.feedback.folderUrl`, `pullCommand`, `skillUrl`) and `feedback.resolved` (with `data.feedback.resolution`).

## Coolify

`docker-compose.coolify.yml`, deployed as a Docker Compose resource. You set four values; Coolify generates the rest.

| Value | Who sets it |
|---|---|
| `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `ADMIN_EMAILS` | You (`${VAR:?}`). |
| `SERVICE_URL_SERVER_3000` | Coolify, from the server's domain `https://feedback.example.com:3000`. `PUBLIC_URL` reads `SERVICE_URL_SERVER`. |
| `SERVICE_PASSWORD_64_AUTH` | Coolify: the auth secret (`BETTER_AUTH_SECRET`). |
| `SERVICE_USER_POSTGRES`, `SERVICE_PASSWORD_64_POSTGRES` | Coolify: the Postgres user and password, used by Postgres and in `DATABASE_URL`. |
| `SERVICE_HEX_64_S3SECRET`, `SERVICE_HEX_64_GARAGERPC`, `SERVICE_PASSWORD_64_GARAGEADMIN` | Coolify: Garage's S3 secret key, cluster secret and admin token. |

- No host ports and no Traefik labels; Coolify's proxy routes the domain.
- Garage builds from `deploy/garage.Dockerfile` with `deploy/garage.toml` baked in.
- No optional variable is passed. To pin one, add it to the server's environment in the file and under Environment Variables.
- Local transcription: `COMPOSE_PROFILES=whisper`; `WHISPER_URL` already points at it.
- Validate: `OIDC_ISSUER=https://accounts.google.com OIDC_CLIENT_ID=x OIDC_CLIENT_SECRET=y ADMIN_EMAILS=you@example.com docker compose -f docker-compose.coolify.yml config -q` (warns about the `SERVICE_*` values).
