# Status: in-page reviewer toolbar (Part 2, step 4)

Branch `p4/reviewer-ui`. Decisions D-134 to D-140 (written as D-117 to D-123 on the branch; renumbered at the merge into main, which already held D-117 to D-133).

## What is built

| Part | Where | What it does |
|---|---|---|
| Toolbar shell | `apps/extension/entrypoints/capture.content/review/Pill.svelte` | A 44 px dark launcher bottom-right with the count of unsent notes and a red dot while a trace runs. Awake, a dark pill of 32 px buttons: comment, element screenshot, rectangle, arrow, freehand (six colours), voice note, Start or Stop trace (red dot and elapsed time), notes list, hide pins, Send, close. Drag the grip to any corner; the corner is kept in `chrome.storage.local`. Mounted in the existing shadow root (closed in release builds). |
| Keys | `review/Review.svelte` | `c s r a f t v l h x` while awake and not typing, Esc one level back, Ctrl or Cmd+Shift+. to wake and hide from anywhere. Works in the closed root of the release build (D-135). |
| Comment on an element | `review/state.svelte.ts`, `review/page.ts` | Hover outline plus the name the agent will get (role and accessible name, else test id or selector). The click is blocked from the app and pins a numbered note with the inline composer: label and short selector, text box, camera, voice, intent and severity, Cancel and Add. Enter adds, Shift+Enter is a new line, Esc cancels. |
| Highlight text | same | Native selection; a "Comment T" chip beside it opens the composer with the quote. The highlight stays on the page with the pin. |
| Draw on the page | same, SVG layer in `Review.svelte` | Rectangle, arrow, freehand (perfect-freehand) in document coordinates, so drawings scroll with the page. Each drawing opens the composer with a crop of the drawing plus 16 px, the drawing flattened in. |
| Element screenshot | same, `lib/bg/review.ts` | `s` then a click: the page hides its UI for two frames, the worker crops `captureVisibleTab` to the element at 1x CSS pixels, the composer shows the image. The composer's camera adds an image to any note. |
| Voice notes | `entrypoints/offscreen/main.ts` (`note-start`, `note-stop`), `lib/bg/review.ts` | One on a comment (composer mic) or on its own for the page or the running trace (`v`, pill mic). Microphone only, Opus WebM, kept in IndexedDB until Send. |
| 60 s context | `packages/shared/src/areas/reviewer.ts` (`contextFromEvents`) | Each note carries the console errors, page errors and failed requests of the 60 s before it, read from the tab's ring; the composer says how many, the comment button shows a dot while there are some (D-138). |
| Pins and list | `review/Review.svelte`, `review/ItemList.svelte` | Pins follow their element (or sit at the start of a drawing), survive reloads and navigations in the tab (the tab wakes by itself when it has unsent notes or a trace), hide with `h`, preview on hover, open on click for edit or delete. The list shows the tab's notes, notes from other pages of the tab with their path, Discard all and Send. |
| Start and Stop trace | `review/state.svelte.ts` | Calls `trace.start`, `trace.stop`, `trace.get` of the trace work package. Stop sends the open notes onto the trace first. While a trace runs each note is also an `annotation` event in the tab's ring, so the span engine makes it an action. Without the trace package the button is disabled with a tooltip. |
| Submit | `lib/bg/review.ts` | Send uploads crops (asset kind `feedback`) and voice notes (`voice-note`), then `POST /api/v1/recordings/:id/feedback`: onto the running trace's capture, or into a new capture of kind `feedback` whose events are the errors and requests the notes attached. A toast offers to open it. Retries are safe (clientId). |
| Server | `apps/server/src/lib/server/feedback/service.ts`, `routes/api/v1/recordings/[id]/feedback/+server.ts`, `db/schema/feedback.ts`, `drizzle/0008_feedback_items.sql` | `feedback_item` table, create (creator seat, claims the caller's assets) and list (viewer and share links, media URLs through the member or share proxy). Job `transcribe-note` transcribes each voice note with the configured `Transcriber` and stores WebVTT and text on the item. Recording kind `feedback`; its card image is the first crop. |
| Viewer and dashboard | `apps/server/src/lib/components/feedback/FeedbackList.svelte`, `viewer/CaptureView.svelte`, `dashboard/CaptureCard.svelte`, `packages/shared/src/areas/dashboard.ts` | The capture page lists the notes in pin order with crop, quote, comment, audio player and transcript, and the attached errors and requests. Dashboard type filter "Feedback"; untitled submits read "X's feedback". |

## What is not built or not verified

- Owner taste moves left out: shrink-when-idle to three icons (M-04), the command menu (M-06), pause page motion (M-16), multi-element group notes (M-14), pin stacking and author initials (M-20), key rebinding (M-09), drag onto an X to hide (M-03), reload prompt for a newer deployment (M-32), threads and resolve from the page (M-23).
- The locator packet is the existing `TargetRef` from `@toolbar/capture`; the locator work package's route files and `__svelte_meta` are not wired into the notes yet.
- The `.feedback/<id>/` folder, MCP tools and the Markdown share page do not include feedback items yet (hand-off work package: read `GET /api/v1/recordings/:id/feedback`; `n` is the `aNN` number).
- Notes on a trace stay in the extension until Send or Stop trace in the pill; a trace stopped from the popup leaves them for a later Send, which then makes a separate `feedback` capture.
- Crops are not masked by the production preset (the Jam-style screenshots are not either); zero-integration's presets will need to cover both.
- Transcription was checked with the local whisper.cpp only; the hosted provider is the transcription work package's.
- With the zero-integration branch merged, content scripts run only on project origins: the reviewer e2e and the release test then need the lab origin granted first, as its own suite does.
- Not tested on Nuru or a Next.js app (step 5).
